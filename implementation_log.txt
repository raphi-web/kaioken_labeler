Rationale and measurements that do not belong in source comments. Newest

## 2026-10-09 — mean-shift as the wand's fourth source (Senpai's idea)

PCA(3 bands) -> uint8 -> cv2.pyrMeanShiftFiltering(sp=7, sr=25,
maxIter=10, maxLevel=1), then the spectral RMS measure on the filtered
image. Motivation: "finer tolerance" on the embeddings -- the embed IoU
curve is flat (everything 0.04..0.14 scores the same), because the field
itself is soft. Mean-shift pre-converges each material to one near-constant
colour, which turns the tolerance into a cliff you can aim at.

Validation before building (probe on 026.tif + labels): intra/inter class
distance ratio 0.642 (raw spectral) -> 0.268 (mean-shift filtered), i.e.
2.4x sharper class separation. Cost ~0.25 s per 512px tile, cached per
image. maxLevel=1 (no pyramid) keeps boundaries pixel-sharp -- the whole
point of the source.

Bench: bench_wand.py sources, 385 regions in 20 tiles of the NEW dataset:

| source | mean IoU | median | IoU>=0.5 | wins vs spectral | corr |
|---|---|---|---|---|---|
| mean-shift | **0.641** | 0.647 | **70.1%** | 206/385 | 0.888 |
| spectral | 0.617 | 0.644 | 65.2% | — | — |
| sam | 0.478 | 0.460 | 46.0% | 80/385 | 0.705 |
| embed | 0.476 | 0.445 | 46.2% | 107/385 | 0.637 |

Mean-shift is the BEST source on this dataset at every aggregation -- and
note the whole table moved vs the morning's embed bench (spectral 0.543 ->
0.617, embed 0.507 -> 0.476): that bench ran on the OLD dataset's 470
regions; these are the new dataset's 385. Spectral stays the default by
decision; mean-shift is one click away and measurably stronger here.

Mean-shift tolerance curve: peak 0.08 (IoU 0.432), band within 10% of
peak 0.05..0.10, collapses past ~0.15 (fills jump the sharpened boundary).
-> MS_TOL_FLOOR 0.02, MS_TOL_CEIL 0.14, slider 50 = 0.08. Same
"narrow band on purpose" reading as embed: a sharp field compresses the
useful tolerances, and the slider now spans exactly that.

Design notes:

- Field is RMS (spectral units), NOT cosine: the win is colour collapse,
  and RMS on collapsed colours is the sharpest cheap measure. No centring
  or unit-norm -- those serve cosine fields only.
- PCA per image, not per dataset: a tile is what the user wands at, and
  its own statistics are the honest reference. Eigen-axes from valid
  pixels only, so nodata borders cannot tilt them.
- cv2 demands exactly 3 uint8 channels: 1-2 band projects get the last
  component repeated (RMS weights repeats like distinct channels).
- No new dependency: opencv-python-headless was already in for polygons.
- Availability is unconditional (cv2 is a hard dependency), so the UI
  button never greys out -- unlike sam/embed.
- test_meanshift is pure property tests on synthetic stacks (convergence,
  determinism, range, degenerate masks); test_wand adds the invariants
  over the real project plus a sharpness regression guard: mean-shift's
  intra/inter ratio on the image's own labels must beat raw spectral by
  >10%, or the filter has become decoration.
- Default-band pin: 006.tif interior click selects 8.98% at tol 0.08.

## 2026-10-09 — Road class removed; dataset swapped to 138 tiles

The training-side taxonomy dropped Road (old id 1) and shifted every id above
it down by one: Agriculture-Green 2→1, Raw-Earth 3→2, Meadow 4→3, Forest 5→4,
Shrub 6→5, Water 7→6, Snow 8→7, Wetland 9→8, Synthetic Nodata 10→9. The
label rasters on disk were already remapped by the user (verified: value
union across all 138 masks is exactly 0..8, no 9/10 leftovers); this change
aligns the app with them.

Touched: `project_config.json` classes, `CLASS_PRESETS["sentinel2"]` in
backend/project.py, the frontend fallback `CLASSES` in src/constants.js, the
README class table, and the test fixtures that named Road.
`WAND_TOL_SEEDS` needed no renumbering — the seeds are keyed by class NAME
precisely so an id shift cannot mis-map a material's measured tolerance
(Road's entry was deleted as dead weight). `next_class_id` stays 11: the
high-water mark is deliberately never lowered, so old id 10 (Synthetic
Nodata) is not handed to a future class — stale masks outlive configs.

The dataset under input_images/label_raster was swapped wholesale at the same
time (138 tiles named NNN.tif; previously 79 files 00..33/e2_*/s2_*). Two
dataset facts broke fixtures that pinned old filenames:

- test_sam's golden fixtures were captured from the old 00.tiff, which still
  sits at the repo root; IMAGE now points there and skips when absent.
- test_masks pinned label_raster/00.tif; now scans for a mask with both
  nodata and class pixels (any file exercises the conversion).
- The new masks are heterogeneous: int32/-9999 (98), int32/255 (16),
  int16/-9999 (24) — and 16 of the int32/255 files declare nodata 255 while
  STORING -9999. read_label_mask handles them correctly (range-keyed, not
  sentinel-keyed); the round-trip test now asserts label semantics + class
  pixel byte-equality universally, full byte-equality only for files whose
  declared nodata is what they store, and prints the inconsistent list.
  Worth fixing on the producer side eventually; the app is unaffected.
- The wand band-calibration tests click fixed points, which are only
  in-band on some tiles of the new dataset; they are pinned to measured
  tiles (SAM default → 003.tif, embed default → 026.tif, nodata → 001.tif)
  via the existing indirect-parametrize mechanism.

The embed constants from the morning bench (peak 0.08, band 0.04..0.12) were
measured on the OLD dataset's 470 regions. The encoder itself was trained on
this same tile distribution, so the band is expected to hold; re-run
`backend/bench_wand.py sources` after this swap if the wand ever feels off.

## 2026-10-09 — auto-encoder embedding as the wand's third source

The labeling build grew a third magic-wand distance source, `embed`, from
`auto_encoder/embedding.onnx` (contract: `auto_encoder/ONNX.md`). The model
replaces the never-wired prithvi encoder folder, which was deleted; a backup
lives outside the repo.

### Design decisions

- **New source, not a replacement.** The wand already dispatched on
  `source` ("image" | "sam"); "embed" is a third arm of that switch, so every
  downstream invariant (additivity, per-sample budgets, negatives, protect,
  global mode) is inherited and re-tested rather than reimplemented.
- **Pixel resolution, no upsample.** The graph encodes fixed 128×128 patches
  of raw DN; `EmbedService` tiles, batches (≤64 patches/run) and stitches to
  (8, H, W) at one cell per pixel, with edge-padding for non-multiples of
  128. Unlike SAM's coarse feature grids, the click's own distance survives
  exactly (pinned by `test_the_embed_field_is_exact_at_the_click`).
- **Same field maths as SAM.** `Wand._cosine_field` was extracted from the
  SAM path: map pixel → grid (identity here), mean-centre + unit-normalise
  the stack, one tensordot per click. Centring is load-bearing: measured on
  00.tiff's labels, the intra/inter cosine-distance ratio improves from
  0.043 (raw) to 0.018 (centred).
- **Hard gate at 10 bands.** The graph's input is fixed `(B, 10, 128, 128)`
  int16 DN; projects are band-count-configurable, so `Api._embed_unavailable`
  refuses non-10-band projects with a message instead of an ORT shape error,
  and the UI button greys out (refetched per project, since the gate is
  project-shaped while SAM's model-file check is global).
- **Spectral stays the default** (user decision, confirmed by the bench below).
- **One tolerance across classes** for embed, same policy as SAM: per-class
  optima have not been measured, and inventing seeds would dress a guess up
  as evidence. Each embedding source remembers its own slider position
  (`samTolerance` / `embedTolerance` settings fields).

### Bench: `backend/bench_wand.py sources --images 20`

470 labeled regions across 20 project images, each source at its own best
tolerance (per-region oracle over its swept range):

| source | mean IoU | median | IoU ≥ 0.5 |
|---|---|---|---|
| spectral | 0.543 | 0.550 | 55.5% |
| embed    | 0.507 | 0.534 | 52.8% |
| sam      | 0.469 | 0.478 | 48.1% |

Complementarity vs spectral:

| pair | wins over spectral | correlation | per-region union |
|---|---|---|---|
| embed | 205/470 | 0.658 | 0.605 (+11%) |
| sam   | 173/470 | 0.518 | 0.606 (+12%) |

Reading: embed lands between spectral and SAM overall, but wins on 44% of
regions with a moderate correlation — it fails where spectral fails
differently, which is the only property that justifies a third source. On
the 3-region pilot run embed looked best of all three (0.744); the 470-region
run corrected that, and the tooltip copy was written from the big run.

Embed tolerance curve (mean IoU per tolerance, 470 regions):

```
0.02 0.272 | 0.04 0.319 | 0.06 0.327 | 0.08 0.328 <- peak
0.10 0.318 | 0.12 0.303 | 0.14 0.294 | 0.16 0.278
0.20 0.253 | 0.30 0.211 | 0.40 0.189
band within 10% of peak: 0.04..0.12
```

→ `EMBED_TOL_FLOOR = 0.02`, `EMBED_TOL_CEIL = 0.14`, slider 50 = 0.08 =
peak, so the useful band spans slider 14..71 and the default sits on the low
side of the decay, matching the spectral wand's "over-selection costs more
than under-selection" policy.

### Encoding cost

One 512×512 tile = 16 patches = one batched run ≈ 0.09 s on CPU (Ryzen 5
PRO 8540U), vs seconds for a SAM2 encode. The first embed click on an image
pays it; the result is cached per image in `Wand._stacks["embed"]` and in
`EmbedService`, keyed so display-band changes do not re-encode (the encoder
consumes all 10 bands regardless).
